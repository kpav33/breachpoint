# Breachpoint — Project Intro

A quick orientation for anyone joining the project. Read this first, then
`docs/PLAN.md` for the current phase and `CLAUDE.md` for the working rules.

## What the game is

Breachpoint is a **top-down 2D tactical shooter in the style of Counter-Strike**,
playable in the browser. Two teams — attackers (T) and defenders (CT) — fight
over bomb sites in short rounds: Ts try to plant and defend a bomb, CTs try to
stop them or defuse it. Between rounds you earn money from kills and round wins
and spend it on better weapons, so there's an economy/strategy layer on top of
the action.

You can play solo against AI bots (Practice) or online via the lobby (Quick
Play matchmaking, private rooms with join codes).

The art direction is deliberately **flat and geometric** — circle players,
clean-lined walls, solid-color floors. The "feel" comes from the juice layer
(tracers, screen shake, particles, decals) and a fog-of-war vision cone: you
only see what your character could actually see.

## The stack

| Piece | Used for |
|---|---|
| TypeScript | Everything, client and server |
| Phaser 3 | Client rendering only |
| Vite | Dev server + client build |
| Tiled-format JSON | Maps (generated by `tools/generate-map.mjs`, editable in Tiled) |
| Colyseus + Node | Authoritative multiplayer server (port 2567) |
| Docker + Fly.io | Server deployment (`docs/DEPLOY.md`) |

Placeholder art and audio are procedurally generated by scripts in `tools/`, so
real assets can be swapped in later without code changes.

## The one big idea: engine-free simulation

The project was built **bots-first but multiplayer-ready from day one**. That
worked because of three non-negotiable rules (also in `CLAUDE.md` — they are
enforced, not aspirational):

1. **`src/core/` never imports Phaser.** The simulation (movement, collision,
   raycasting, weapons, vision, pathfinding) is pure TypeScript: plain-data
   state + functions that transform it. The same applies to `src/match/`
   (rounds, economy, bomb) and `src/ai/` (bot brains). The Node server imports
   these exact files unbuilt and runs them authoritatively; Phaser only
   *renders* the resulting state. ESLint enforces the import boundary.
2. **Input is data.** Keyboard/mouse and bots alike produce plain
   `InputCommand` objects; only `core/simulation.applyInput()` moves a player.
   Those same objects are what travel over the wire in multiplayer.
3. **Fixed-timestep simulation** at `TICK_RATE` (from `core/config.ts`);
   rendering interpolates between ticks. This is what makes deterministic
   server replay — and therefore fair netcode — possible.

Because of these rules, multiplayer was a bolt-on, not a rewrite: the server
already had the whole game, and the client became one more source of input
commands.

## Where things live

- `src/core/` — pure simulation: types, config, simulation, collision,
  raycast, vision, weapons, pathfinding
- `src/match/` — rounds, economy, bomb logic, game modes (headless, runs on
  the server)
- `src/ai/` — headless bot brains + objective assignment (Ts plant, CTs
  defend/rotate), shared by client and server
- `src/game/` — Phaser-side: entities, systems (input, vision rendering,
  effects, audio), map loading, theme tokens
- `src/scenes/` — Boot, Menu, Lobby, Game (Practice/OnlineGame subclass it),
  UI (HUD), Pause
- `src/net/` — wire protocol (shared with the server) + browser Colyseus
  client wrapper
- `server/` — authoritative Colyseus server; imports `src/core` + `src/match`
  + `src/ai` directly, no Phaser
- `public/assets/` — sprites, map JSON, tilesets, audio
- `tests/` — headless match-logic tests (`npm test`), plain Node runner using
  `--experimental-strip-types` — the same mechanism the server uses to load
  TypeScript, so zero extra tooling

## Systems worth knowing about

- **Vision / fog of war:** a real visibility polygon (raycast against merged
  wall segments) intersected with a ~110° aim cone plus a small 360° awareness
  circle. Geometric, not faked.
- **Bots:** state-machine AI with A\* pathfinding and objective logic, running
  identically on client (Practice) or server (filling online matches).
- **Server hardening:** inputs are clamped server-side and buys validated via
  `tryBuy`, including a prototype-pollution guard (`__proto__` key injection)
  on weapon lookups. Speed/fire-rate can't be forged because the server owns
  the simulation.
- **Debug overlay:** toggle with backtick. It visualizes every invisible
  system — collision grid, wall segments, raycasts, visibility polygons, bot
  states, A\* paths. If you add a system with invisible state, extend it.

## Day-to-day commands

- `npm run dev` — client dev server
- `npm run server` — game server on port 2567
- `npm test` — headless simulation/match tests
- `npm run lint` — includes the core/server import-boundary rules
- `npm run build` — typechecks client + server, bundles the client
